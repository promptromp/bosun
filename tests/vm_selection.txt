# Which parts of the Mac VM suites a change reaches beyond what the parts' `covers` say (tools/vm_select.py:
# `tests/sandbox.sh mac --changed <ref>`, CI's install job). One rule per line:
#
#   all <suite>[,<suite>...] <glob>   (or `all * <glob>`) a change to it runs those suites whole
#   none <glob>                       no VM part needs it: the smoke suite and the unit tests are enough
#   year <glob>                       a change to it gives work's afternoon update a year of data (else 30 days)
#   minutes <suite>[/<part>] <n>      the estimate a selection prints: a suite's clone and setup, or a part
#
# Globs match the path from the repository root, whole: `*` within a folder, `**` through any number of them.
# `<file>#<function glob>` names functions of a shell file read by function (lib/common.sh): a glob without `#`
# never matches such a file. The suites: run (tests/install_e2e.sh), work (tests/work_e2e.sh), app
# (tests/app_e2e.sh), live (tests/sandbox/live.sh, paid).
#
# For a changed file the order is: `all` (those suites whole), then the parts that cover it, and if neither,
# `none` (nothing to run); a file in none of them is unknown, which runs run, work and app whole (never live).
# tests/unit/test_vm_selection.py fails on a tracked file (or a function of lib/common.sh) that falls in none, and
# says what to add. Prefer a part's `covers` to `all`, and `all run,work,app` to `none` when unsure.
